# 課題2

* 以下のように中間テーブルを作成すれば、Issueテーブル二はnullableのフィールドが存在しなくなる&複数名アサインすることが可能

```mermaid
erDiagram
    USER {
        int user_id PK
        string name
    }

    ISSUE {
        int issue_id PK
        string title
    }

    ISSUE_ASSIGNEE {
        int issue_id PK FK
        int user_id FK
    }

    USER ||--o{ ISSUE_ASSIGNEE : assigned_to
    ISSUE ||--|| ISSUE_ASSIGNEE : has
```

## NULLが必要か？

- NULLは「値が存在しない・未設定・不明」という状態を表すためのフィールド
    - そのため、真にNULLという値を入れるべきケースは存在する
- ただNULLが存在することで、難しさが発生する場合はある
    - SQLの比較や結合が複雑になる（三値論理の問題）
    - インデックス作成をするときに、パフォーマンスの面で影響が出る
- そのため場合による
    - 今回はそもそも複数担当者が定義できる設計の方が柔軟性があるため、テーブルを切り分けるべき
