# 課題2-1

1. スタイル崩れ
    - 例：ボタンの余白（padding）が変更されたことで、テキストがはみ出してレイアウトが崩れた。ビジュアル差分で検知可能。
2. 想定外の色変更
    - 例：テーマカラーを一部更新した際、誤って重要な警告メッセージの背景色まで変わり、警告が目立たなくなった。差分画像で検出可能。
3. コンポーネント再利用による予期せぬUI変化
    - 例：共通ヘッダコンポーネントの文言を修正したら、別画面のタイトル表示まで変わってしまった。ストーリー間で共通部品の変化を検知できる。

# 課題2-2

1. 仕様上の正しさ
    - 例：日付フォーマットを「unixtime → yyyymmdd」に変更し、見た目は変化しているが、本来unixtime表示が正しかったケース。見た目だけで正誤は判断できない。
2. 動的データの正誤
    - 例：在庫数「10」と表示されているが、実際のAPIレスポンスでは在庫ゼロ。UI上は数字が表示されるため見た目では気づけない。
3. アニメーションやレスポンスのタイミング依存バグ
    - 例：ドロップダウンが展開される速度が極端に遅くなった。静的なスナップショットでは動作速度やインタラクションの不具合は検知できない。
